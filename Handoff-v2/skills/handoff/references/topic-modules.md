# Topic modules

Add the sections for the chat's topic type in place of `<Topic-specific sections>` in the template. These are the things that type of chat loses most when it restarts.

## Study / academic review
- **Course & exam:** course name, exam/assignment, date, format (MC, written, open-note), chapters in scope.
- **Session mode:** what was happening, such as explaining new material, active recall, practice exam, flashcards, or cheat sheet. Note any skill or structure in use (e.g. "slide-breakdown format", "exam-review active recall mode").
- **Coverage map:** topics fully covered ✅ · partly covered 🟡 · not yet covered ⬜. This is what tells the next chat where to go.
- **Weak spots:** each concept the user got wrong or was shaky on, with the specific question or mistake and the correct answer. Note repeats ("missed 2×").
- **Strong spots:** concepts the user nailed and that shouldn't be re-drilled.
- **Score log:** quiz/practice scores so far (e.g. "Ch 4 recall: 7/10").
- **Question queue:** questions already asked (so they aren't repeated) and the next ones planned.
- **Materials:** slides, textbook chapters, notes the user uploaded (also list them under Files to re-attach).

## Research / career / planning
- **Question being answered:** the actual research question, stated sharply.
- **Findings so far:** each with source link and date. Mark (unverified) where needed.
- **Options compared:** a compact table of options × criteria if one was built.
- **Criteria & constraints:** what the user said matters (budget, location, timeline, values).
- **Action items:** things the user committed to doing, with deadlines.
- **Contacts / names:** people, companies, programs mentioned and their relevance.

## Technical / code / build
- **Project & stack:** repo/project name, language, framework, environment.
- **What's working / what's broken:** current status per component.
- **Changes made:** files touched and what changed (not full code, unless it's a short critical snippet).
- **Errors in play:** the exact error message text plus what's been tried.
- **Constraints:** rules like "no new deps", "don't touch X", style rules.
- **Next steps:** an ordered list.

## Decision / purchase
- **Item & situation:** what's being decided, with exact model/config/price.
- **Comparison table:** options × price, warranty, key specs, risks.
- **Deadlines:** return windows, sale end dates, with the actual dates computed.
- **Decision rule:** the "if X by date Y, then do Z" logic the user agreed to.

## Creative (writing, design, music)
- **Piece & purpose:** what it is, audience, tone.
- **Current draft state:** latest version, or where to find it (file to re-attach).
- **Style rules:** voice, constraints, things the user liked and disliked in past drafts.
- **Feedback log:** what the user asked to change, in order.

## Casual / hobby (gaming, TV, misc)
- **What the user is doing:** game/show/activity and where they're at (level, episode, build).
- **Preferences expressed:** likes and dislikes that shaped recommendations.
- **Recommendations given:** and how the user reacted.
- Keep this type short. Casual chats rarely need more than ~30 lines.
